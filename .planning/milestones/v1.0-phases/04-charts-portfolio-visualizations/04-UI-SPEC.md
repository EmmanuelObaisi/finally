> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Scope: ticker selection from the watchlist, the main price chart, the P&L treemap heatmap, the portfolio value (P&L) chart, and explicit empty states for the watchlist, positions table, heatmap and P&L chart (UI-07, PORT-07, PUI-03, PUI-04, PUI-07). ## Spacing Scale

Same scale as Phases 2 and 3 (multiples of 4):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Gap between a title and its sub-label inside empty/error states (`gap-1`) |
| sm | 8px | Heatmap tile inner padding (`p-2`), gap between title-bar value groups (`gap-2`) |
| md | 16px | Title-bar horizontal padding (`px-4`), gap between title and its stat group (`gap-4`) |
| lg | 24px | Empty/error/waiting overlay padding (`p-6`) |
| xl | 32px | Retry button height (`h-8`) |
| 2xl | 48px | Not used |
| 3xl | 64px | Not used |

Exceptions (all multiples of 4, fixed component dimensions, not spacing tokens):
- Every new panel has a 40px title bar (`h-10`), identical to the watchlist and positions title bars. No column-label rows in the chart panels.
- Panel minimum heights at >= 1024px: main chart, heatmap and P&L chart `min-h-40` (160px) so a short viewport degrades by scrolling nothing and clipping nothing inside a panel. Below 1024px panels get fixed natural heights: main chart `h-80` (320px), heatmap `h-64` (256px), P&L chart `h-64` (256px).
- Heatmap tile text thresholds (not spacing): ticker label shown when the tile is at least 48px wide and 24px tall; P&L % line added when the tile is at least 48px tall. Smaller tiles show no text (title and aria-label still carry it).
- Heatmap tiles are separated by a 1px `border-panel` (a border, not spacing); the treemap uses `paddingInner(0)`.
- Selected watchlist row indicator: 2px left border (a border, not spacing).
- No 12px, 20px or other off-scale spacing; no arbitrary `[..px]` spacing. The only arbitrary values permitted are grid templates (`lg:grid-rows-[...]`).

## Color

No new tokens. 60/30/10 holds: `surface` remains dominant (page, input fills), `panel` is the secondary surface for every chart panel, accent stays at its reserved uses.

| Role | Value | Usage in this phase |
|------|-------|---------------------|
| Dominant (60%) | `#0d1117` (`surface`) | Page background |
| Secondary (30%) | `#161b22` (`panel`) | Main chart, heatmap and P&L chart panels and their canvases (chart backgrounds are transparent over `panel`). Neutral heatmap tile and selected/hover watchlist row: `#1c2128` (`raised`). Borders and horizontal chart gridlines: `#30363d` (`border`) |
| Accent (10%) | `#ecad0a` (`accent`) | Unchanged reserved list below |
| Destructive | `#f85149` (`down`) | No destructive action exists in this phase. `down` is the market-loss color (negative change %, loss heatmap tiles, negative P&L delta) |

Status and series colors used here:

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| `fg` | `#e6edf3` | Chart titles and values, all heatmap tile text, P&L delta of exactly zero |
| `muted` | `#8b949e` | Axis text, crosshair lines, title-bar sub-labels, "--", overlay body text |
| `primary` | `#209dd7` | Main chart line (2px), P&L chart line (2px) and its area fill (`rgb(32 157 215 / 0.28)` at the top fading to `rgb(32 157 215 / 0)` at the bottom), selected-watchlist-row left border, Sparkline (unchanged). Series color never encodes direction (extends Phase 2 decision 2) |
| `up` / `down` | `#3fb950` / `#f85149` | Heatmap tile fills (tinted, see rule), signed change % and P&L delta text via `toneClass`. Never a chart line color |
| `secondary` | `#753991` | Not used in this phase |

Accent reserved for: (1) the "FinAlly" wordmark in the header, (2) the `:focus-visible` outline (2px, offset 2px) on every interactive control, now including the watchlist ticker-select buttons and the chart Retry buttons. Nothing else. Accent is never used for chart lines, tiles, selection, or hover.

Heatmap tile fill (binding):
- Fill = `up` (rgb 63 185 80) for profit or `down` (rgb 248 81 73) for loss at alpha `0.15 + 0.35 * min(|pnl_percent| / 10, 1)`, so alpha runs 0.15 (about 0%) to 0.50 (10% or more, saturated). A position whose `pnl_percent` rounds to `0.00` uses the neutral fill `raised` (`var(--color-raised)`).
- Contrast of `fg` text over the strongest tint on `panel`, computed with the WCAG relative-luminance formula: profit about 5.5:1, loss about 6.8:1. Lighter tints are higher. Text is always `fg`, never `up`/`down`, because green text on a green tint fails contrast.
- Direction is never by color alone: each tile with room for a second line prints the signed P&L % ("+3.20%", "-1.05%"), and every tile carries an `aria-label` with the signed value.
- The fill is computed by a pure function `tileFill(pnlPercent)` in `frontend/src/lib/heatmap.ts`; the rgb triplets there mirror `up`/`down` the same way `chartTheme.ts` mirrors theme tokens. These two lib files are the only places literal color values are allowed.

Chart canvas colors (add to `CHART_COLORS` in `chartTheme.ts`, mirroring tokens): `border: "#30363d"`, `raised: "#1c2128"`, existing `primary` and `muted`. Chart canvas options (shared, via one `baseChartOptions()` function in `chartTheme.ts` reused by the main and P&L charts): transparent background, `textColor: muted`, `fontFamily` = the system stack, `fontSize: 12`, horizontal gridlines `border`, vertical gridlines hidden, `rightPriceScale.borderColor` and `timeScale.borderColor` = `border`, crosshair lines `muted` dashed with `labelBackgroundColor: raised`.

### Selection rules (`selectionStore.sync`, called from a `WatchlistPanel` effect whenever its `view` changes)

- `loading` or `error` view: set `status` accordingly and keep `selected` unchanged.
- `ready` view: set `status = "ready"`. If `selected` is non-null and is in the list, keep it. Otherwise select the first ticker in response order (AAPL on a fresh database); if the list is empty set `selected = null`.
- Only watchlist rows select (**researcher default**). A held ticker that is not on the watchlist has no chart; heatmap tiles and positions rows are not clickable in this phase. If the selected ticker is removed, the main chart falls to the first remaining ticker through the rule above.
- Selection is not persisted: every page load selects the first watchlist ticker (UI-07 "a default ticker is selected on load").

## Main chart (UI-07)

Data and library:
- `createChart` in a `useEffect` that runs once on mount (the chart persists across ticker changes); `chart.addSeries(LineSeries, ...)`; `chart.remove()` in cleanup; `vi.mock("lightweight-charts")` in jsdom tests. v5 API only (`addSeries`, `UTCTimestamp` casts), as in `Sparkline.tsx`.
- Data source: the existing per-ticker market buffer `useMarketStore(s => s.spark[selected])`: one point per second keyed by arrival time, same-second ticks replace the last point, capped at 300 points, so the chart shows the last 5 minutes since page load (**researcher default**: no new buffer, no cap change, no extra backend call; the main chart and the sparkline of the same ticker always agree). Title text "Since page load" tells the user the window.
- On ticker change: `series.setData(toData(buffer))` then `chart.timeScale().fitContent()`. On each new buffer: `setData` then `fitContent()` (as the sparkline). The same `toData` mapping is shared with `Sparkline.tsx`.

Options (in addition to `baseChartOptions()`):
- `autoSize: true`; `layout.attributionLogo` left at its default (true): the main chart shows the TradingView logo (Phase 2 decision 1).
- `handleScroll: false`, `handleScale: false` (**researcher default**: the chart is a glanceable readout; `fitContent()` on every update would fight user pan and zoom). The crosshair stays on (`CrosshairMode.Normal`) so hover reads price and time.
- `rightPriceScale: { visible: true, scaleMargins: { top: 0.1, bottom: 0.1 } }`; `timeScale: { visible: true, timeVisible: true, secondsVisible: true, rightOffset: 0, tickMarkFormatter: (t) => fmtClock(t) }`; `localization.timeFormatter: (t) => fmtClock(t)`.
- Series: `color: primary`, `lineWidth: 2`, `priceLineVisible: true`, `lastValueVisible: true`, `crosshairMarkerVisible: true`, `priceFormat: { type: "price", precision: 2, minMove: 0.01 }`.
- Container: `data-testid="main-chart"`, `data-ticker="{TICKER}"`, `data-points="{N}"`, `role="img"`, `aria-label="{TICKER} price since page load, now {fmtMoney}"`.

States (see State Matrix for copy and test ids). The chart box is always mounted so the chart instance survives state flips; overlays sit above it with `bg-panel` and `absolute inset-0`.

## Heatmap (PUI-03)

- Data: `usePortfolioStore` positions joined with live prices (`useMarketStore(s => s.prices)` restricted to held tickers via a shallow selector, same price rule as the positions table: `prices[ticker]?.price ?? position.current_price`). Per position: `value = quantity * price`, `pnlPercent` from `livePosition(position, price)`.
- Weight: tile area is proportional to `value`. Positions with `value <= 0` are skipped; if that leaves zero tiles the empty state shows.
- Layout: `hierarchy({ children }).sum(d => d.value)`, `treemap().tile(treemapSquarify).size([width, height]).paddingInner(0).round(true)`, where `width` and `height` come from `useElementSize` on the tiles box. Leaves are ordered by cost basis descending (`market_value - unrealized_pnl` from the server position), ties by ticker (**researcher default**: cost basis does not change between trades, so tiles do not swap places as prices tick; ordering by live value would reshuffle whenever two weights cross). Width or height of 0 renders no tiles.
- Rendering: container `data-testid="heatmap-tiles"`, `relative`, `role="list"`, fills the panel body (no padding). Each tile is a `<div role="listitem">` with inline `left/top/width/height` in px and `backgroundColor: tileFill(pnlPercent)`, `border border-panel`, `overflow-hidden`, `p-2`, text `fg`.
- Tile content: line 1 ticker (Body 600, `truncate`); line 2 `fmtPct(pnlPercent)` (Label). Thresholds are in the Spacing exceptions. Every tile has `title="{TICKER}: {fmtMoney(value)}, {weight}% of positions, P&L {fmtSigned(pnl)} ({fmtPct(pnlPercent)})"` where `weight = value / sum(value) * 100` to one decimal, and an `aria-label` with the same sentence. The tile has `data-pnl="up|down|flat"` (flat when `pnl_percent` rounds to 0.00) and `data-weight` (the one-decimal number).
- Live updates: tiles recompute from the store on every price frame (at most 10 to 20 tiles). Motion: `transition-[left,top,width,height,background-color] duration-300 ease-out motion-reduce:transition-none` so weight drift glides instead of jumping. No flash animation on tiles.
- Not interactive: tiles are not buttons, have no hover style beyond the `title`, and are not focusable (**researcher default**).

## P&L chart (PUI-04, PORT-07)

Data:
- `historyStore.load()` calls `GET /api/portfolio/history` (`{history: [{total_value, recorded_at}]}`, ascending, at most 2000 points; the seeded $10,000 snapshot is the first point on a fresh database). `recorded_at` ISO strings convert to UTC seconds; points sharing a second keep the last one; the series stays strictly ascending.
- Refetch triggers (and no others, so the snapshot table is never flooded; the server also min-interval guards): (1) on mount, (2) every 30 000 ms via `setInterval` while the panel is mounted, skipped when a fetch is already in flight, (3) whenever the `portfolio` object in `usePortfolioStore` changes identity (a trade response, a reconnect `load()`; a trade records a snapshot server-side, so this makes a new trade add a point), (4) the Retry button.
- Live "now" point: `buildPnlSeries(history, nowSeconds, liveTotal)` appends `{ time: floor(now), value: liveTotals(portfolio, prices).total }` when the portfolio has loaded and `floor(now)` is greater than the last history time (otherwise it is omitted). The live point is recomputed at most once per second (keyed by `floor(now)`) and the series is replaced with `setData` followed by `fitContent()`. The live point is never persisted or posted; it is the same number as the header total.
- Failed refetch after data exists keeps the stale chart and sets no error UI (same rule as the positions panel). Failure with no data ever loaded shows the error state.

Options (in addition to `baseChartOptions()`):
- `autoSize: true`; `layout.attributionLogo: false` (the main chart carries the logo and the footer carries the attribution link); `handleScroll: false`, `handleScale: false`; crosshair `CrosshairMode.Normal`.
- `timeScale: { visible: true, timeVisible: true, secondsVisible: false, rightOffset: 0, tickMarkFormatter }` where the formatter returns `fmtDay(t)` for `TickMarkType.Year | Month | DayOfMonth` and `fmtClock(t).slice(0, 5)` (`HH:mm`) for `TickMarkType.Time | TimeWithSeconds`; `localization.timeFormatter: (t) => fmtDateTime(t)`.
- Series: `chart.addSeries(AreaSeries, { lineColor: primary, topColor: "rgb(32 157 215 / 0.28)", bottomColor: "rgb(32 157 215 / 0)", lineWidth: 2, priceLineVisible: false, lastValueVisible: true, crosshairMarkerVisible: true, priceFormat: { type: "price", precision: 2, minMove: 0.01 } })`. The line and fill are `primary`; direction is carried by the title-bar delta text, not the chart color.
- Container: `data-testid="pnl-chart"`, `data-points="{N}"` (number of points currently in the series including the live point), `role="img"`, `aria-label="Portfolio value over time, now {fmtMoney(total)}"`.

## Interaction and Motion

- Selection: click or Enter/Space on a watchlist row switches the main chart in the same render; no animation on the switch (the line is replaced and fitted). The Sparkline of every row is unchanged.
- Hover and crosshair on the two charts show the Lightweight Charts price and time labels (`raised` background, `fg` text). No custom HTML tooltips.
- Heatmap tiles glide on weight drift (300 ms transition, off under `prefers-reduced-motion`). Chart canvases have no entrance animation.
- Skeletons use `motion-safe:animate-pulse` as in Phases 2 and 3.
- Disconnected state (`status === "disconnected"`): numeric title-bar values dim to `opacity-60`; chart canvases and heatmap tiles are not dimmed (the connection indicator is the signal; dimming a canvas gives no extra information and the lines are not "stale numbers"). Chart lines simply stop extending. Status `reconnecting` does not dim.
- Reconnect: the existing `connected` transition already re-fetches the portfolio (Phase 2), which changes the portfolio identity and so triggers a history refetch. The watchlist panel re-fetches when in error, which re-syncs selection.
- Focusable elements added: watchlist select buttons and the Retry buttons. All use the accent focus ring. Tab order in the watchlist row: select button, then remove button.
- Keyboard: no shortcuts. Charts and tiles are not focusable.
- No confirmations and no destructive actions in this phase.

## Decisions Recorded

Researcher defaults (no discuss-phase, no questions possible; each is the option most consistent with PLAN.md sections 2 and 10, the prior UI-SPECs and the fixed stack; the user may override any):

1. Workspace order: main chart, then heatmap and P&L chart side by side, then the trade bar, then the positions table. The trade bar sits next to the positions it changes; the charts get the top of the screen. Row weights 5fr / 4fr / auto(72px) / 4fr.
2. Main chart window is the existing sparkline buffer (last 5 minutes since page load, 300 points, one point per second). No backend history endpoint exists for prices, and PLAN.md defines the chart as built from the SSE stream. Raising the window later means raising `SPARK_CAP`, which also lengthens the sparklines.
3. Selection only from the watchlist rows; heatmap tiles and positions rows do not select. A selected ticker that leaves the watchlist falls back to the first remaining ticker. Selection is not persisted.
4. Charts are not pannable or zoomable (`fitContent()` runs on every update), crosshair readout only. Series color never encodes direction; green and red keep one meaning (price direction and P&L) and appear only as title-bar text and heatmap tile tints.
5. Heatmap: area by live market value, color by `pnl_percent` saturating at 10%, text always `fg`, leaves ordered by cost basis so tiles do not reshuffle on ticks, 300 ms glide transitions, no clicks. Fill alpha capped at 0.50 so `fg` text keeps at least 5.5:1 contrast.
6. P&L chart is an `AreaSeries` in `primary`, with a live "now" point, refetched every 30 s and on every portfolio change. The title-bar delta compares the live total with the fixed $10,000 seed.
7. Lightweight Charts attribution: the main chart keeps the default logo (as Phase 2 decision 1 promised); the P&L chart and sparklines hide it; the footer attribution and tradingview.com link stay.
8. CONFIRMED BY THE USER 2026-10-09 (empty only when never traded): ROADMAP criterion 4 says that "with no positions" the P&L chart shows an explicit empty state, while criterion 3 says the chart starts with the seeded $10,000 point. This spec reconciles them as: empty state when no positions are held AND history has at most one point (the user has never traded); once any trade has happened the chart renders even if every position is later closed, so closed-out history is not hidden. If a literal "no positions always means empty" is wanted, drop the history condition; no other UI change.
9. Heatmap tiles whose value is 0 or less are not drawn; a portfolio where every position is worth 0 shows the empty state.
10. Phase 5 hand-off: a docked chat column narrows the workspace, so Phase 5 owns re-flowing the mid row.

Impacts on existing code the executor must handle: `page.tsx` workspace composition; `WatchlistRow.tsx` (select button, selected style, row click, `stopPropagation` on remove); `WatchlistPanel.tsx` (selection sync effect, pass-through props); `Footer.tsx` (comment only); `chartTheme.ts` (new colors and `baseChartOptions()`); `Sparkline.tsx` may reuse the shared `toData` mapping and `baseChartOptions()`; `WatchlistRow` and `WatchlistPanel` tests gain the select button and `data-selected`; the selection store is reset in `beforeEach` like the portfolio store.
