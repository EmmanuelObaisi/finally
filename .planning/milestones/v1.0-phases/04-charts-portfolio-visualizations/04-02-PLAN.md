## Phase Goal

**As a** FinAlly user, **I want to** see the selected ticker's price chart, a P&L heatmap of my positions and my portfolio value over time, **so that** I can read my portfolio and the market at a glance.

(Story assembled from the ROADMAP Phase 4 `**Goal:**` line; the Goal line is not written as a user story. See the planner return.)

<objective>
Put the main price chart in the workspace and make watchlist rows select it. A default ticker (the first watchlist row) is charted on load; clicking a row, or Enter on its select button, switches the chart in the same render; every chart state (loading, error, empty, waiting, populated) has its own overlay.

Purpose: UI-07. Also lays the shared chart pieces plans 04-03 and 04-04 reuse: `ChartOverlay`, `baseChartOptions()`, `toData`, the time formatters, and the workspace grid.
Output: `selectionStore`, selectable watchlist rows, `MainChartPanel`, `ChartOverlay`, chart theme and time formatters, the re-slotted workspace, unit tests and `test/portfolio-charts.spec.ts`.

Tracer: Task 1 is the thinnest live path through every layer this plan touches: watchlist GET -> selection store -> row click -> `MainChartPanel` -> Lightweight Charts line fed by the SSE buffer, proven by host Playwright against the static export. Task 2 pins the selection rules; Task 3 adds every chart state and pins them.
</objective>

| T-04-07 | Information disclosure | Main chart error state | low | mitigate | Fixed UI-SPEC copy only; no server body or status is shown (Task 3 tests) |
| T-04-08 | Denial of service (client) | Chart instance churn on ticker switch | low | mitigate | The chart is created once on mount and removed on unmount; a test asserts one `createChart` call across a switch (Task 3) |
| T-04-SC | Tampering | Package installs | low | accept | No packages are installed by this plan; `lightweight-charts` 5.2.1 is already pinned |
