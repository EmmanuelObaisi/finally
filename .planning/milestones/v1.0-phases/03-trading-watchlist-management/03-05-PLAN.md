## Phase Goal

**As a** FinAlly user, **I want to** buy and sell shares and curate my watchlist, **so that** every position stays priced and every change shows immediately.

<objective>
Let the user curate the watchlist from the panel: an add form above the table and an always-visible remove control on every row, both locked while a change is in flight, both rendering the server's response list immediately and the server's error text inline.

Purpose: UI-06, the browser side of WL-02/WL-03, and the end-to-end proof that a held ticker keeps streaming after it leaves the watchlist (roadmap Phase 3 criteria 4 and 5). Completes the IN-01 fix.
Output: `addTicker`/`removeTicker`, the add block, the remove column, unit tests, `test/watchlist.spec.ts`, the disposition update.

Tracer: Task 1 is the thinnest live path through every layer this plan touches: add form submit -> `addTicker` -> real backend add -> response list rendered -> new row priced by SSE, proven by host Playwright. Task 2 adds removal, the held-ticker case and every mutation state.
</objective>

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-18 | Tampering (XSS) | `watchlist-message` rendering `Invalid ticker: <input>` | medium | mitigate | Rendered through `FormMessage` as a React text node; no raw-HTML prop in `frontend/src` (03-03 acceptance grep still holds) |

| T-03-20 | Tampering | Ticker text in the DELETE path | low | mitigate | `encodeURIComponent` on the path segment; the server matches by parameterized SQL and answers 404 for anything not stored |
| T-03-SC | Tampering | Package installs | low | accept | No new packages |
</threat_model>
