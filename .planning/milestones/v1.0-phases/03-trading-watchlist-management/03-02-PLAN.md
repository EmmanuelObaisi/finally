## Phase Goal

**As a** FinAlly user, **I want to** buy and sell shares and curate my watchlist, **so that** every position stays priced and every change shows immediately.

<objective>
Let the user curate the watchlist through the API: `POST /api/watchlist` adds a validated, priced ticker and starts streaming it; `DELETE /api/watchlist/{ticker}` removes it, and a held ticker keeps streaming because both routes go through `tracking.sync_ticker`.

Purpose: WL-02, WL-03 and the watchlist half of MKT-08. Closes the Phase 2 carry-over 02-REVIEW IN-03 (`remove_ticker` evicts held tickers). Plan 03-05 puts these routes behind the watchlist panel; Phase 5 chat calls `add_to_watchlist` / `remove_from_watchlist` with its own `request.app.state`.
Output: watchlist mutation cores and routes, tests, the interface docstring note, and the disposition update.

Tracer: Task 1 is the thinnest live path through every layer this plan touches: HTTP body -> `normalize_ticker` -> `source.add_ticker` -> price check -> `INSERT OR IGNORE` -> `build_watchlist` response, answered by a real uvicorn process against a scratch database. Task 2 expands it with removal and the held-ticker rule.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> `POST /api/watchlist`, `DELETE /api/watchlist/{ticker}` | Untrusted ticker text in a body or a path segment |
| FastAPI -> market source | An add makes the source track and (for Massive) poll a client-chosen symbol |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-08 | Tampering | Ticker input on add | medium | mitigate | `normalize_ticker` (ASCII check, upper-case, `fullmatch` of `[A-Z][A-Z.]{0,9}`) before any market or DB call; parameterized SQL only; DELETE upper-cases only ASCII input and matches by parameter |
| T-03-09 | Denial of service | Unknown symbols polled forever | low | mitigate | `add_to_watchlist` ends in `finally: await sync_ticker(...)`, which untracks a symbol that got no price or whose add failed (Task 1 test for ZZZZ) |
| T-03-10 | Tampering | Held position losing its price on removal (IN-03) | medium | mitigate | DELETE calls `sync_ticker`, which keeps a held ticker tracked; Task 2 test proves the price survives and no unpriced-position error is logged |
| T-03-11 | Denial of service | Long input echoed in `Invalid ticker: ...` | low | accept | Contract requires quoting the input; single local user; the body size is bounded by the server |
| T-03-SC | Tampering | Package installs | low | accept | This plan installs nothing |
</threat_model>
