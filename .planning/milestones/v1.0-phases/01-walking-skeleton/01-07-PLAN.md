## Phase Goal

**As a** developer, **I want to** build and run an end-to-end skeleton of FinAlly on this machine (local and in Docker) against one frozen API/SSE contract, **so that** every later phase adds one visible capability to an app that already runs.

(Story assembled from the ROADMAP Phase 1 `**Goal:**` line and the ROADMAP Overview, as in plans 01-01 to 01-05.)

<objective>
Close review warning WR-04: `getHealth()` never checks `res.ok`, so a 404, 500 or 503 that returns the contract's `{"error": "..."}` envelope is cast to `Health`, `status` is undefined, and the page's `api-status` renders empty instead of "down". The page must show "down" on any non-2xx response (FND-03).

Purpose: `frontend/src/lib/api.ts` is the typed client that every later API call copies (Phases 2-5). Fixing the pattern now stops error bodies from being read as success data across the app.
Output: `frontend/src/lib/api.ts` (status check), `test/health-status.spec.ts` (new host Playwright spec), WR-04 marked fixed.

Tracer: Task 1 is the thinnest end-to-end path: real browser -> exported page -> `getHealth()` -> a non-2xx health response (mocked at the browser with `page.route`) -> "down" on screen, served by the real backend through the existing Playwright `webServer`. Task 2 proves the full local suite and a clean rebuild, then records the fix.
</objective>
