## Phase Goal

**As a** FinAlly user, **I want to** chat with FinAlly, which understands my portfolio and executes trades and watchlist changes on my behalf, **so that** I can analyze and act on my portfolio in plain language.

(Story assembled from the ROADMAP Phase 5 `**Goal:**` line; the Goal line is not written as a user story. See the planner return.)

<objective>
Run a whole chat turn on the server. `POST /api/chat` loads the portfolio, watchlist and the last 20 messages, makes one LLM call through the `complete()` seam, validates the structured reply, executes each requested action through the same services as the manual endpoints (capped at 10 trades and 10 watchlist changes, each in its own transaction), persists the user and assistant rows in one transaction, and answers with the message, the per-action results and the fresh portfolio and watchlist. `GET /api/chat/history` returns the stored conversation. LLM failures become a graceful assistant reply that executes nothing. Then write the D-07, D-08, D-10, D-11 and D-13 decisions into the API contract.

Purpose: CHAT-01, CHAT-04..08, the route half of CHAT-09, and the chat-flow half of TEST-03.
Output: `backend/app/chat.py`, `backend/app/chat_store.py`, router wiring, `backend/tests/test_chat.py`, `backend/tests/test_chat_store.py`, and the contract edits.

Tracer: Task 1 is the thinnest live path through every layer this plan touches: HTTP POST -> `run_turn` -> prompt -> `complete()` mock seam -> `ChatReply` parse -> `place_trade` -> SQLite persistence -> JSON response -> `GET /api/chat/history`, proven against a real uvicorn process with `LLM_MOCK=true`. Task 2 pins every failure, cap, ordering, persistence and concurrency edge; Task 3 writes the contract.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> `POST /api/chat` | Any local client sends free text that reaches the LLM prompt and is stored |
| model output -> trade and watchlist services | The model's structured reply decides which writes happen |
| backend -> logs and response bodies | Exception text from the provider could carry sensitive details |
| concurrent requests -> SQLite | Parallel turns, trades and history reads share one database |
