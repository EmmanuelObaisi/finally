## Phase Goal

**As a** FinAlly user, **I want to** chat with FinAlly, which understands my portfolio and executes trades and watchlist changes on my behalf, **so that** I can analyze and act on my portfolio in plain language.

(Story assembled from the ROADMAP Phase 5 `**Goal:**` line; the Goal line is not written as a user story. See the planner return.)

<objective>
Build the browser's chat data layer and the two push channels that make a chat reply refresh the rest of the terminal. Add the chat wire types and calls, the pure action-sentence builder, a `chatStore` that owns the conversation and the send lifecycle, and a `watchlistStore` push channel that `WatchlistPanel` listens to. A reply applies its `portfolio` through the existing `applyTrade` (header, positions, heatmap and P&L chart already read that store) and publishes its `watchlist` to the panel.

Purpose: PUI-05 (send lifecycle, history, panel state) and PUI-06 (reply-driven refresh) at the data layer, so plans 05-04 and 05-05 only render. Wave 1: independent of the backend plans; it depends only on the frozen `POST /api/chat` and `GET /api/chat/history` shapes.
Output: `ChatAction`, `ChatMessage`, `ChatReply` types, `postChat`, `getChatHistory`, `actionText`, `chatStore`, `watchlistStore`, the `WatchlistPanel` push effect, and their tests.

Tracer: Task 1 is the thinnest live path through every layer this plan touches: `useChatStore.send` -> `postChat` (stubbed fetch) -> reply -> `usePortfolioStore.applyTrade` and `useWatchlistStore.publish` -> a rendered `WatchlistPanel` row appears. Task 2 pins the store rules, the sentences, the panel edge cases and the API helpers.
</objective>
