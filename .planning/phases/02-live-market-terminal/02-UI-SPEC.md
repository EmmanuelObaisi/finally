### Formatters (`format.ts`, the only place numbers are formatted; Intl `en-US`)

| Function | Output | Rules |
|----------|--------|-------|
| `fmtMoney(n)` | `$1,234.50` | 2 dp, thousands separators, `$` prefix; negative `-$12.30` |
| `fmtQty(n)` | `1.5`, `10` | up to 6 dp, trailing zeros trimmed, separators |
| `fmtSigned(n)` | `+12.30`, `-12.30`, `0.00` | 2 dp, sign except zero |
| `fmtPct(n)` | `+0.63%`, `-0.63%`, `0.00%` | `change_percent` is ALREADY in percent units (0.0632 means 0.0632%): use decimal style with 2 dp and `signDisplay: "exceptZero"`, then append `%`. | all | `--` | `null`, `undefined`, `NaN`, `Infinity` return `--`. Never render `NaN`, `0` or an empty string for a missing value |

Rows in the watchlist always use `fmtMoney` for price (consistent with the header).

## Interaction and Motion

### Price flash (UI-05)

- Applies to the Price cell's inner `<span class="block ...">` only (right-aligned, `px-2`, `rounded-sm`). Classes: `animate-flash-up` / `animate-flash-down`, 500ms ease-out, from a 40% tint of `up` / `down` to transparent. No JS timers.
- Trigger rule (binding): flash when an incoming SSE frame carries a ticker whose `timestamp` is greater than the stored one AND `direction` is `up` or `down`. Compare timestamps, not just direction: a source that does not refresh every ticker (Massive polling) re-sends the old update with the same timestamp and must not re-flash.
- A `flat` tick never clears or starts a flash. The first value a ticker ever receives (REST seed or first frame) never flashes.
- Restart: increment `flash.seq` only on up/down updates and set `key={flash.seq}` on the span so a new tick restarts a running animation. The span also carries `data-flash="up|down|none"` = last non-flat direction since page load (`none` before the first move). Peak contrast of `fg` text over the 40% tints is about 6.8 (green) and 8.2 (red) on `panel`.
- Rate: at most 2 flashes per second per cell, under the WCAG 2.3.1 three-per-second threshold. No `prefers-reduced-motion` override for the flash (it is a color fade that carries data); the loading skeleton pulse uses `motion-safe:animate-pulse`.

### Sparkline (UI-04)

- `createChart(el, opts)` in `useEffect`; `chart.addSeries(LineSeries, ...)`; `chart.remove()` in cleanup; `vi.mock("lightweight-charts")` in jsdom tests.
- Options: `autoSize: true`; `layout: { background: transparent, textColor: muted, attributionLogo: false }`; `grid` lines hidden; `crosshair.mode = CrosshairMode.Hidden`; `handleScroll: false`, `handleScale: false`; `leftPriceScale.visible = false`; `rightPriceScale: { visible: false, scaleMargins: { top: 0.15, bottom: 0.15 } }`; `timeScale: { visible: false, rightOffset: 0 }`. Series: `color: primary (#209dd7)`, `lineWidth: 1`, `lastValueVisible: false`, `priceLineVisible: false`, `crosshairMarkerVisible: false`. Container `pointer-events-none`, `aria-hidden="true"`, explicit height 24px.
- Data: one point per second keyed by client arrival time (UTC seconds, strictly ascending; same-second ticks replace the last point), capped at 300 points (about 5 minutes). `setData` once with the existing buffer on mount, then `update()` per tick, then `timeScale().fitContent()` so the whole buffer always fills the width.
- Fewer than 2 points: the container renders empty (no line, no placeholder). The line appears at the second second of data and fills in progressively. The stroke is always `primary`; sparkline color does not encode direction.

### Connection indicator (UI-02, UI-03)

State machine from RESEARCH Pattern 4 (one `EventSource` for the whole page, closed on unmount):

| `data-status` | Dot color | Label | `aria-label` and `title` | Entered when |
|---------------|-----------|-------|--------------------------|--------------|
| `connected` | `up` `#3fb950` | Live | "Connected: streaming live prices" | `onopen` |
| `reconnecting` | `warn` `#d29922` | Reconnecting | "Reconnecting: price stream interrupted, retrying" | initial state before the first `open`, or `onerror` while `readyState` is CONNECTING |
| `disconnected` | `down` `#f85149` | Offline | "Disconnected: no price stream for 5 seconds or more, retrying" | `reconnecting` persists 5000 ms without an `open`, or `readyState` is CLOSED (non-200 response) |

- The initial page-load state is `reconnecting` (label "Reconnecting") until the first `open`; this is accepted and not specially labeled.
- Chromium keeps retrying about once a second and never reaches CLOSED when the server dies, so the 5 s timer (not `readyState`) is what turns the dot red. On `open` the dot returns to green immediately and the timer is cleared. On CLOSED the hook recreates the `EventSource` with backoff 1, 2, 4 then 10 s.
- When status is `disconnected`, numeric values (watchlist price and change cells, header total and cash) render at 60% opacity (`opacity-60`) so stale numbers do not look live; labels, tickers and sparklines are unchanged. They return to full opacity on reconnect. Status `reconnecting` does not dim.
- Each time the status becomes `connected`, the page re-fetches `GET /api/portfolio` and, if the watchlist is in the error state, `GET /api/watchlist`. This is the only retry logic besides the explicit Retry button.

### Other interaction

- No hover tooltips beyond `title` attributes named above. No click handlers on rows (Phase 4 adds ticker selection). No keyboard shortcuts.
- Focusable elements this phase: the Retry button (error state) and the footer link only. Both use the accent focus ring.
