## Phase Goal

**As a** FinAlly user, **I want to** open the app and watch the 10 default tickers stream live in a dark terminal, with $10,000 cash shown and a live connection indicator, **so that** I can see the market move before I trade.

(Story assembled from the ROADMAP Phase 2 `**Goal:**` line and the PROJECT core value; see the planner return.)

<objective>
Let a user with a Massive (ex-Polygon) API key watch real prices in the same terminal, with no frontend change: a REST poller behind the same `MarketDataSource` interface, chosen by the factory from `Settings.massive_api_key`, that uses the paid snapshot endpoint and falls back to Grouped Daily closes on the free plan within its 5 calls/min budget.

Purpose: MKT-05 and the Massive half of MKT-06 and TEST-01. The capability decisions for the Massive surface are recorded in `.planning/phases/02-live-market-terminal/COVERAGE.md` (snapshot and Grouped Daily integrated; everything else an explicit opt-out).
Output: `backend/app/market/massive_client.py`, the factory branch, and stub-client tests (no API key exists in this environment, RESEARCH A7).

Tracer: Task 1 is the thinnest path through every layer this plan touches: `Settings.massive_api_key` -> factory -> `MassiveDataSource.start` -> (stub) `get_snapshot_all` -> `PriceCache` -> `price_frames`. Tasks 2 and 3 expand it with the free plan, edge cases, failure handling and factory selection.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| backend -> api.massive.com (HTTPS) | API key leaves the process; prices come back from a third party |
| environment / .env -> Settings | `MASSIVE_API_KEY` secret enters process memory |
| PyPI -> backend/.venv | `massive` and `urllib3` enter the build |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-10 | Information disclosure | API key in logs or responses | high | mitigate | The key lives only in `Settings` and the client header; no code logs the client, key or settings; Task 3 test asserts a failing poll's log output lacks the key; no endpoint returns it |
| T-02-11 | Spoofing | TLS to api.massive.com | high | mitigate | Client defaults keep certifi verification on (Task 1 acceptance greps for `verify=False`/`cert_reqs`); the only allowed fix for an unknown issuer is `truststore.inject_into_ssl()` |
| T-02-12 | Denial of service | Free plan 5 calls/min budget | medium | mitigate | Start costs 2 calls; weekends skipped locally; walk-back capped at 5; end-of-day refresh every 900 s; tickers added in end-of-day mode cost no call (Task 2) |
| T-02-13 | Tampering | Untrusted price values in Massive responses | low | mitigate | Fallback chain skips missing or zero prices; an absent ticker never gets a price (Task 2 tests) |
| T-02-SC | Tampering | `massive` install | high | mitigate | Version approved at the 02-01 blocking-human gate (precondition on Task 1); `==` pin and committed `uv.lock`; Docker uses `uv sync --locked` |
</threat_model>
