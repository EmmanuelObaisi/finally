## Phase Goal

**As a** FinAlly user, **I want to** buy and sell shares and curate my watchlist, **so that** every position stays priced and every change shows immediately.

(Story assembled from the three parts of the ROADMAP Phase 3 `**Goal:**` line; see the planner return.)

<objective>
Make trading real on the server: `POST /api/portfolio/trade` fills market orders atomically at the cached price, rejects invalid orders with the `{"error"}` envelope and changes nothing, appends to the trades log, records a snapshot, returns the updated portfolio, and keeps the streamed tickers equal to watchlist union positions.

Purpose: PORT-02..PORT-06, the trade half of MKT-08, and TEST-02. Plans 03-03 and 03-04 put this endpoint behind the trade bar and positions table; plan 03-02 reuses `tracking.py` and `DomainError` for watchlist add/remove; Phase 5 chat calls `place_trade` with its own `request.app.state`.
Output: `errors.py` domain errors, `db.transaction`, `tracking.py`, `trading.py`, the router include, the fixed-price test double, the TEST-02 suite, and the frozen rejection messages in the contract.

Tracer: Task 1 is the thinnest live path through every layer this plan touches: HTTP body -> strict `TradeRequest` -> `place_trade` -> `execute_trade` inside `BEGIN IMMEDIATE` -> trades row, position, cash, snapshot -> response, answered by a real uvicorn process against a scratch database. Task 2 pins the money rules with the TEST-02 suite; Task 3 adds the tracking rule for unwatched tickers.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> `POST /api/portfolio/trade` | Untrusted JSON body (ticker, quantity, side) moves money |
| FastAPI -> SQLite at DB_PATH | Cash, positions, trades log and snapshots |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Tampering | `TradeRequest`, `execute_trade` quantity | high | mitigate | `Field(strict=True, allow_inf_nan=False)` rejects NaN, infinities, strings and booleans; `execute_trade` rounds to 6 dp and tests `not quantity > 0` (also on the Phase 5 path that bypasses the model); CHECK constraints `cash_balance >= 0`, `quantity > 0` are the backstop (Task 1, Task 2 tests) |
| T-03-02 | Tampering | Concurrent trades (double spend) | high | mitigate | Validation and every write run inside one `BEGIN IMMEDIATE` transaction via `db.transaction`, so writers serialize; Task 2 two-thread test proves one winner and cash never negative |
| T-03-03 | Tampering | SQL built from the ticker | medium | mitigate | `normalize_ticker` (ASCII, upper-case, `fullmatch` of `[A-Z][A-Z.]{0,9}`) before any use, and every value is a `?` parameter |
| T-03-04 | Information disclosure | Error bodies | low | mitigate | `DomainError` messages are fixed templates; anything else (including a CHECK `IntegrityError`) is the generic 500 `{"error": "Internal server error"}` from the Phase 1 handler |
| T-03-05 | Denial of service | Symbols left streaming after failed buys | low | mitigate | `place_trade` ends in `finally: await sync_ticker(...)`, so an untracked symbol is dropped after a rejected buy (Task 3 tests) |
| T-03-06 | Tampering | Micro-quantity orders whose cost rounds to $0.00 | low | accept | At most half a cent per fill of simulated money for the single local user; contract fixes 2 dp money and 6 dp quantities |
| T-03-07 | Repudiation | Trade history | low | mitigate | The trades row (uuid, side, quantity, fill price, `executed_at`) is written in the same transaction as the cash and position change, and the table is append-only |
| T-03-SC | Tampering | Package installs | low | accept | This plan installs nothing (RESEARCH Package Legitimacy Audit: no packages this phase) |
