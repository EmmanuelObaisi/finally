## Phase Goal

**As a** FinAlly user, **I want to** see the selected ticker's price chart, a P&L heatmap of my positions and my portfolio value over time, **so that** I can read my portfolio and the market at a glance.

(Story assembled from the ROADMAP Phase 4 `**Goal:**` line; the Goal line is not written as a user story. See the planner return.)

<objective>
Serve portfolio value history. Add `GET /api/portfolio/history`, which returns the newest 2000 snapshots oldest first and, before reading, records one snapshot only when the minimum interval has passed AND the total value changed (user decision 2026-10-09). Name the guard in the API contract. First, gate the phase's two npm packages behind one human approval, so plan 04-04 can install them.

Purpose: PORT-07. Plan 04-03 plots this history in the P&L chart; the guard keeps "never traded" equal to "exactly one history point", which the P&L empty state (UI-SPEC Decision 8) relies on, and keeps the 30 s chart poll from flooding the table.
Output: `backend/app/history.py`, `now_iso(now)` in `db.py`, router wiring, `backend/tests/test_history.py`, the contract sentence, and the approved package list.

Tracer: Task 2 is the thinnest live path through every layer this plan touches: HTTP GET -> `get_history` -> `record_if_due` under `BEGIN IMMEDIATE` -> `build_portfolio` valuation -> SQLite read -> JSON, proven against a real uvicorn process. Task 3 pins every guard edge with tests and writes the contract sentence.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> `GET /api/portfolio/history` | Any local client (one or many tabs) can poll the route; each request may write one row |
| request handler -> SQLite | The guard's read-then-insert must be atomic across concurrent requests |
| npm registry -> frontend/node_modules | Third-party code enters the build in plan 04-04 after this plan's approval |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Denial of service | `portfolio_snapshots` growth from repeated history requests (write amplification) | medium | mitigate | `record_if_due` inserts only after `MIN_INTERVAL_SECONDS` AND a changed value; reads are `LIMIT 2000`; tests pin both (Task 3) |
| T-04-02 | Tampering | Concurrent requests both inserting | low | mitigate | Read-latest and insert run in one `transaction(conn)` (`BEGIN IMMEDIATE`); the concurrency test proves at most one insert (Task 3) |
| T-04-03 | Tampering (integrity) | Client-supplied snapshot values | low | mitigate | The route takes no body or query; the value is `build_portfolio(conn, cache)["total_value"]`; POST is answered 404 (Task 3 test) |
| T-04-04 | Tampering (SQL injection) | History queries | low | mitigate | `?` placeholders only, as in the rest of the backend (Task 2 action) |
| T-04-05 | Information disclosure | Error responses | low | mitigate | Failures use the existing `{"error"}` envelope with fixed text for 500s; the route returns only `total_value` and `recorded_at` |
| T-04-SC | Tampering | npm installs for the phase (d3-hierarchy, @types/d3-hierarchy) | high | mitigate | Blocking-human package-legitimacy checkpoint (Task 1) before plan 04-04 installs; exact pins and the committed lockfile in 04-04 |
</threat_model>
